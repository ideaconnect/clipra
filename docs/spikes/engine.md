# Spike: layered compositing on Media3 (#6)

**Question.** Can Media3 render the Clipra layer model, or does Clipra need its own compositor? The model is any content on any layer, gaps between clips, 16 blend modes and transitions across cuts. Both preview and export have to go through it.

**Answer.** Clipra composites in its own GL effect and uses Media3 around it:
- **Clipra:** the layer compositor (`LayerCompositor`, a Media3 `GlEffect`), which draws every layer of a frame.
- **Media3:** the timeline clock, preview (`CompositionPlayer`), encoding and muxing (`Transformer`) and audio mixing.

On the emulator, an export with five layers, gaps, Screen, Multiply, a dissolve, a photo and a text card is correct at every checked frame. Export speed and preview frame rate still have to be measured on real phones.

## What Media3 1.11.1 offers, and where it stops

From the Media3 1.11.1 sources:

- **Multi-sequence compositions.** Media3 can composite several video sequences. The compositor (`DefaultVideoCompositor` with `DefaultCompositorGlProgram`) draws the inputs back to front, with sequence 0 on top. It blends with fixed alpha blending only (`glBlendFuncSeparate(SRC_ALPHA, ONE_MINUS_SRC_ALPHA, ...)`). `VideoCompositorSettings` controls only the output size and each input's position, scale, rotation and alpha.
- **The compositor can't be replaced for export.**
  - `MultipleInputVideoGraph` creates `new DefaultVideoCompositor(...)` itself.
  - Transformer's `VideoSampleExporter` hardcodes `MultipleInputVideoGraph.Factory` whenever a composition has more than one video track. There is no `setVideoGraphFactory` on `Transformer.Builder`.
  - `CompositionPlayer.Builder.setVideoGraphFactory` exists (experimental), but a custom compositor there would make preview and export differ.
- **Blend modes:** Multiply, Screen and the other 14 modes need the colour already on the canvas. The default compositor can't provide that.
- **Transitions:** cross-fading within one sequence isn't supported (Media3's composition guide says so). Two A/B sequences with alpha ramps would cover a dissolve only, not wipes or blend-aware transitions.
- **Gaps:** `EditedMediaItemSequence.Builder.addGap()` exists, and Media3 fills audio gaps with silence.

## The approach tested

```
Composition
├── video sequence: one blank 16×16 PNG, as long as the timeline, at the project frame rate
│     effect: LayerCompositor(timeline)   ← draws L1 … Ln for each frame's time
├── audio sequence for L1: clips (audio only, clipped) with gaps
├── audio sequence for L2: …
└── …                                      ← Media3 mixes the audio sequences
```

- The canvas is the only video track, so Transformer uses the single-input video graph and our effect runs on Media3's GL thread.
- For each output frame, `LayerCompositor` clears the canvas to the project background. It then walks the layers bottom to top and draws each clip active at that time:
  - **Video clips:** each has its own `MediaCodec` decoder rendering to a `SurfaceTexture` (external texture) in the same GL context. `VideoFrameSource.frameAt(t)` advances the decoder to the last frame at or before `t`, looking one frame ahead to skip frames when the source frame rate is higher. It seeks when time goes backwards or jumps more than 1 s ahead.
  - **Photos and text:** these are bitmaps, uploaded once as 2D textures.
  - **Normal blend:** the clip is drawn straight onto the canvas with alpha blending.
  - **Other blend modes:** the clip is drawn alone into a clip texture, then a blend pass reads the canvas and the clip and writes the other canvas texture (ping-pong). Screen and Multiply are implemented. The other separable modes are one line each in the same shader, and the non-separable ones (hue, saturation, colour, luminosity) are a few lines more.
  - **Gaps** draw nothing, so the layers below show through.
  - **Dissolve:** the incoming clip overlaps the outgoing one on the same layer and fades in over the overlap (`fadeInUs`). Other transitions become shaders that sample both clips over the overlap.

Code: `core/engine/src/main/kotlin/tech/idct/clipra/core/engine/render/`. The test is `core/engine/src/androidTest/.../render/EngineSpikeTest.kt`, with clips generated by ffmpeg in `core/engine/src/androidTest/assets/spike/`.

```kotlin
val timeline = RenderTimeline(
    width = 1080, height = 1920, frameRate = 30, durationUs = 8_000_000, background = Color.BLACK,
    layers = listOf(
        RenderLayer(listOf(RenderClip("gray", 0, 8_000_000, video("gray")))),
        RenderLayer(listOf(
            RenderClip("red", 0, 4_000_000, video("red")),
            RenderClip("blue", 3_500_000, 2_500_000, video("blue"), fadeInUs = 500_000), // dissolve
        )),
        RenderLayer(listOf(
            RenderClip("green", 1_000_000, 2_000_000, video("green"),
                placement = Placement.Box(0.25f, 0.35f, 0.5f, 0.3f), blend = BlendMode.Screen),
            RenderClip("photo", 5_000_000, 2_000_000, RenderSource.Image(photo),
                placement = Placement.Box(0.05f, 0.05f, 0.4f, 0.2f)),
        )),
        RenderLayer(listOf(RenderClip("cyan", 2_000_000, 1_500_000, video("cyan"), blend = BlendMode.Multiply))),
        RenderLayer(listOf(RenderClip("text", 0, 8_000_000, RenderSource.Image(textCard()),
            placement = Placement.Box(0.1f, 0.82f, 0.8f, 0.1f)))),
    ),
)
val composition = CompositionFactory.create(context, timeline)
Transformer.Builder(context).setVideoMimeType(MimeTypes.VIDEO_H264).build().start(composition, path)
```

The test clips mix sources:
- **Sizes:** 1080×1920, 1920×1080, 1280×720 and 1080×1080.
- **Frame rates:** 24, 30 and 60 fps.
- **Audio:** every clip has AAC audio.

## Results

Run on the Pixel 10 Pro emulator (API 36.1, x86_64, host GPU, `c2.goldfish.h264.decoder`) on 2026-10-28.

**Correctness.** The export's centre pixel matches the expected layer stack at every check:

| Time | Layers at the centre | Expected | Result |
|---|---|---|---|
| 0.5 s | L1 gray, L2 red | red | pass |
| 1.5 s | + L3 green with Screen | yellow | pass |
| 2.5 s | + L4 cyan with Multiply | green | pass |
| 3.75 s | L2 halfway through the dissolve red → blue | purple (128, 0, 128) | pass |
| 4.5 s | L2 blue | blue | pass |
| 6.5 s | L2 and L3 in a gap | L1 gray shows through | pass |

The text card (L5) is white at its position in every checked frame. The export is 1080×1920, 8.0 s long, with mixed audio.

**Numbers (emulator).** These are from two runs. They show that the pipeline works; they are not phone speeds.

| Measurement | Emulator |
|---|---|
| Export, 8 s at 1080×1920, 30 fps, H.264 + AAC | 18.5 to 24.4 s (0.33 to 0.43× real time); 49 to 64 ms per frame in the compositor; 1.9 MB |
| Preview at 540×960, video only | 7 to 13.6 fps composited, 55 to 94 ms per frame in the compositor |
| Seek forward 5 s, into a gap (paused) | 0.52 to 0.66 s to the correct frame |
| Seek back 5 s, two decoders created again (paused) | 1.24 to 1.66 s to the correct frame |
| Decoder start (`c2.goldfish.h264.decoder`, 1080p) | 300 to 800 ms |

Most of the compositor time is spent waiting for the emulator's decoders, one clip after another. The GL passes are cheap at these sizes.

## Decisions

These are written into `docs/architecture.md`, section 4.

1. **Compositor:** Clipra's own GL compositor, run as a Media3 effect on a canvas sequence. It serves both export and preview, so both draw the same pixels. We don't use Media3's multi-sequence video compositing.
2. **Layer ordering:** layers draw from L1 (bottom) up, in the order of the project's layer list. Media3's "sequence 0 is on top" rule no longer applies, because video is a single sequence.
3. **Gaps:** a layer without an active clip draws nothing, and the layers below show through. Audio gaps are `addGap()` in each layer's audio sequence.
4. **Blend modes:** per clip, in the compositor's blend pass. Normal uses fixed alpha blending; the other 15 modes use the ping-pong blend shader.
5. **Transitions:** clips overlap on their layer across the cut, and the incoming clip carries the transition. A dissolve is an opacity ramp. Other transitions are shaders that read both clips' frames over the overlap.
6. **Audio:** one audio-only sequence per layer, mixed by Media3. Per-clip gain, fades and the processed (cleaned, normalized) audio plug in as audio processors or cached files per clip (M5).
7. **Export orientation:** Transformer stores portrait output as landscape with a 90° rotation flag, its default for encoder compatibility, and players show it upright. M8 decides whether to call `setPortraitEncodingEnabled(true)` where the encoder supports it.

## Risks and next steps

- **Preview with audio on the emulator.** With the audio sequences included, `CompositionPlayer` on the emulator delivered a frame only every 1 to 1.5 s, while video-only preview ran at the compositor's speed. The cause wasn't found here. Check first on a real phone (M1-preview). If it persists, preview audio from one pre-mixed PCM track per project, which loudness and voice cleanup produce anyway.
- **Real-time preview on phones.** Decoding happens on the GL thread, one clip after another. Preview should decode 720p proxies (M1-media) and decode ahead on the decoders' own threads into a small `ImageReader`/`HardwareBuffer` queue per clip. Keep decoders alive across short gaps and reuse one decoder per file. Measure on a mid-range and a low-end phone (M11-perf). Hardware decoders have a per-device instance limit: count the clips active at once, and fall back to proxies or software decoding beyond it.
- **Seek latency.** A backward seek recreates decoders and decodes from the previous key frame. Keep decoders for recently active clips, and make proxies with short key frame intervals (1 s).
- **Alpha.** Android bitmaps are premultiplied while the clip shaders assume straight alpha, so the edges of transparent text are slightly dark. Use premultiplied alpha throughout when text rendering lands (M4).
- **Colour and HDR.** The spike is SDR BT.709 only. HDR sources are tone-mapped or rejected, and that is decided in M8.
- **Rotation.** `VideoFrameSource` reports rotated sizes. Applying the rotation in the quad comes with transform support (M2).
